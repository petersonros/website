## O desafio

A disciplina seguia a metodologia ABP (Aprendizagem Baseada em Projetos) — em vez de um exercício isolado, o trabalho precisava partir de algo real. Usei como base o sistema de agendamento da sala de informática que eu já mantinha em produção. A entrega em si foi construída e simulada **dentro da própria plataforma de ensino da Estácio**, cobrindo os temas do currículo de React Native (componentes de interface, persistência de dados, conexões remotas, tópicos avançados) aplicados a esse cenário.

## O que a simulação cobriu

Em vez de código rodando de verdade num app publicado, o trabalho documentou e simulou como esse sistema de agendamento se comportaria numa versão mobile: as telas, o fluxo de autenticação, como os dados trafegariam entre app e backend, e como a mesma lógica de negócio da versão web se traduziria pra um app React Native.

## O que veio depois

Esse TCC acabou virando o ponto de partida de verdade: o sistema de agendamento original evoluiu pro que hoje é o **Conquista**, e a ideia da versão mobile simulada aqui **inspirou diretamente** um app React Native que construí depois, de verdade, com repositório próprio e rodando. Ou seja, o que está documentado neste trabalho é o exercício acadêmico — o app mobile real veio como desdobramento dele, não é a mesma entrega.

## O que fica desse trabalho

Simular uma arquitetura antes de implementá-la de verdade tem valor por si só — força pensar em decisões de estrutura (o que vai pro backend, o que é específico de cada plataforma) sem a pressão de fazer tudo funcionar ao mesmo tempo. Foi esse raciocínio, mais do que o código em si, o que sobrou desse TCC pro projeto que vim a construir depois.
